# M11 — Tenant switcher (remove `TENANT_ID`, sign up / sign in by tenant) ✅

Moved from **one tenant per deployment (static `TENANT_ID` env)** to **all tenants in one
backend, tenant chosen at runtime**. Entering any surface now requires picking a tenant:
type a tenant **name** → sign in if it exists, or sign up (generate a numeric id) if it
doesn't. The data layer was already fully tenant-scoped (M10); this milestone replaced the
*identity source* (env constant → runtime selection) and added the gate + cross-service sync.

## Decisions (confirmed with user)

- **Shared tenant guard, no admin guard** — chat *and* admin (`/agents`, `/knowledge`,
  `/inbox`) sit behind one tenant gate; no separate operator auth.
- **Numeric integer ids** (stored as string), generated by the chat service as `max+1` and
  pushed to the API. Sign-in is by name.
- **`X-Tenant-Id` header** for browser/server → API calls.

## What shipped

- ✅ **Removed `TENANT_ID` / `ACTIVE_TENANT_ID`** from both packages. No code path resolves a
  tenant from env anymore. Seeds hardcode the demo `"default"` tenant; `.env.example` +
  READMEs updated.
- ✅ **API tenant resolution is per-request** (`api/src/lib/tenant.ts` → `tenantFromHeader`):
  `agents`/`knowledge` routers gate on the `X-Tenant-Id` header (400 if missing) via a router
  middleware → `res.locals.tenantId`; `/chat` requires `tenantId` in the body
  (`ChatTurnInput`, no env fallback); the OpenAI facade still resolves via `apiKeyHash`.
- ✅ **Cross-service registry sync**: secret-gated `POST /internal/tenants` on the API
  (`api/src/routes/internal.ts`, `X-Internal-Secret`) upserts a tenant `{id,name}`. On
  sign-up the chat service pushes the new tenant here so its duplicated `Tenant` table has the
  FK target (agents can't be created for an unknown tenant); sign-up rolls back if the sync
  fails.
- ✅ **Chat tenant session**: `POST /api/tenants` signs in / signs up by name (numeric
  `max+1` id), sets an **httpOnly cookie**, and mirrors `{id,name}` to localStorage; `GET`
  returns the current tenant, `DELETE` signs out. `getTenantId()` (`chat/src/lib/tenant.ts`,
  reads the cookie via `next/headers`) replaces the env constant in `/api/users`,
  `/api/conversations`; `/api/chat` uses `conversation.tenantId`.
- ✅ **API-client tenant threading**: browser calls auto-inject `X-Tenant-Id` from localStorage
  via an openapi-fetch `onRequest` middleware (`chat/src/lib/api.ts` + `lib/tenant-client.ts`);
  server-side callers (`fetchAgents`/`fetchAgent`, used by entry routing + escalation) pass the
  header explicitly. `resolveEntryRouting(tenantId, flag)` now takes the tenant.
- ✅ **Shared gate UI**: `TenantProvider` (`components/tenant/tenant-provider.tsx`) wraps the
  app in `layout.tsx` — renders the tenant gate until a tenant is chosen, then exposes
  `useTenant()`. `site-nav` shows the current tenant + a **Switch tenant** control.

## Verified live (both services + real DBs)

- API: `/agents` 400 without header; isolated per `X-Tenant-Id`; `/internal/tenants` 201 +
  idempotent + 400 on missing fields + 401 without secret.
- Chat: guarded routes 400 pre-sign-in; sign-up minted `1`→`2`→`3`; httpOnly cookie set;
  sign-in returned the same id (`isNew:false`); guest user + conversation scoped to the
  tenant.
- Cross-service: creating an agent for a freshly-signed-up tenant succeeded (proves the
  `Tenant` FK row propagated); agent + user lists fully isolated between `default` and the new
  tenant. Test tenants cleaned up afterward (both DBs back to `default`).
- `tsc --noEmit` clean in both packages; chat `lint` clean (one pre-existing unrelated warning).

## Notes / not done

- No schema change was needed (Tenant + `tenantId` already existed from M10), so no migration.
- RAG live-path (Postgres) not re-exercised here — needs `docker compose up`; the knowledge
  routes are header-scoped the same way as agents.
- ✅ Cookie/localStorage desync self-heal is wired into the provider: on mount it shows the
  stored tenant optimistically, then reconciles against `GET /api/tenants` — cookie present →
  adopt it; cookie missing but a name is remembered → re-sign-in to re-mint the cookie; both
  empty → the gate. Verified live: GET returns the cookie tenant / null for missing/stale ids.
